# Выполнение утверждённого плана

Этот режим использует исходный `ai-dev` из рабочей копии. Один утверждённый план сохраняет полный список функций и критериев, очередь задач, зависимости и общий лимит model turns. Каждая задача запускает Codex через существующую подписочную авторизацию. Дополнительного planner turn перед задачей нет.

## Формат плана

JSON имеет `schema_version: 1`, постоянный `plan_id`, `objective`, `budget.max_model_turns`, массивы `features` и `tasks`. Каждая функция задаёт `id`, `title`, непустые `acceptance` и `checks` (массивы argv без shell). Каждая задача задаёт `id`, `feature_id`, `title`, `instructions`, `depends_on`, `allowed_paths` и `checks`. Дополнительно можно указать `context_paths` (до восьми нужных файлов), `model` (`gpt-6-luna` или `gpt-6-sol`) и `reasoning`. По умолчанию используется Luna medium. Циклы и неизвестные зависимости отклоняются до model call.

Файл `work/approved-plan-demo/approved-plan.json` — фактически прогнанный пример с двумя функциями. Это демонстрационный план, а не общая продуктовая спецификация.

## Команды

Запускать из текущей исходной рабочей копии MegaProg, подставив абсолютные пути проекта и утверждённого JSON:

```text
./ai-dev -C PROJECT approved-plan import /absolute/path/to/approved-plan.json
./ai-dev -C PROJECT approved-plan run PLAN_ID
./ai-dev -C PROJECT approved-plan status PLAN_ID --json
./ai-dev -C PROJECT approved-plan resume PLAN_ID
```

Если во время model turn тот же checkout менялся другим процессом, режим
останавливается с причиной `Workspace changed outside task allowlist`. Он не
утверждает, какой процесс сделал правку. Сначала завершите параллельную работу и
просмотрите Git diff, журнал worker и **все** изменившиеся посторонние пути.
Затем можно принять уже законченный model turn одними проверками:

```text
./ai-dev -C PROJECT approved-plan reconcile PLAN_ID --accept-external path/one.py --accept-external path/two.py
```

Список должен точно совпасть с текущими изменениями вне `allowed_paths`.
Нужны завершённый журнал Codex и сохранённая сессия; приёмка записывает хэши,
принятые пути и результат проверок. Она не вызывает модель и не изменяет исходный
патч. Для блокировок старой версии без сохранённых хэшей патча после ручной
проверки требуется ещё `--accept-current-state`. Если код менялся после записи
хэшей, приёмка остановится. Не используйте `resume` для такой блокировки до
сверки: он предназначен для продолжения незаконченного model turn.

Контекстные файлы проверяются перед списанием model turn. Общий предел их
содержимого — 12 КиБ; для большого файла оставьте `context_paths` пустым и дайте
исполнителю прочитать нужные участки из рабочей копии.

`run PLAN_ID --max-tasks 1` останавливается после одной проверенной задачи. Позднее `resume PLAN_ID` в новом процессе продолжает очередь. Повторный запуск завершённого плана не создаёт model turn. При ошибке статус `BLOCKED` сохраняет patch и полные логи; после разбора причины `resume` продолжает ту же задачу и использует сохранённый Codex session ID, если он известен и доступен.

## Что сохраняется и когда функция готова

`.ai-dev/approved-plans/PLAN_ID/plan.json` — неизменяемый реестр требований. `state.json` хранит очередь, сессии, результаты и источник продолжения; `events.jsonl` и `logs/` сохраняют события, вывод Codex и проверки. `plan_digest` связывает state с реестром. Функция получает `VERIFIED` после завершения всех её задач и успешных проверок. После каждой следующей задачи повторяются проверки всех завершённых функций, чтобы увидеть регрессию в общей рабочей копии. Proof ссылается на task IDs, команды, exit codes, логи и отпечаток исходников. Наличие статуса `VERIFIED` не означает установленный релиз или успешность других проектов.

Режим последовательный. Глобальный лимит model turns, существующий `max_attempts`, проверка каталога/квоты и account guard сохраняются. Источники вне task allowlist блокируют приёмку и остаются для разбора; автоматический откат не стирает единственный patch. Ни установка, ни commit, ни push не выполняются.
